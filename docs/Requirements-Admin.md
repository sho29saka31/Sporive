# Requirements: Admin（Sporive）

[Requirements](Requirements.md) の一部。管理者画面(要件定義書 §10)。

## 10-1. アナリティクスダッシュボード

利用者の統計・アナリティクスを表示。開発者自身がプロジェクト発表時に活用できる見せ方も意識する。

- 利用者数・継続率などの基本指標（DAU/WAU、リテンション）
- 負債発生率・達成率などのトレーニング系KPI
- AI提案内容の分析（人気メニューなど）
- プロジェクト成果を示せる指標（利用者数の推移、継続率の変化、負債解消率など）

## 10-2. 管理者権限の区分

- **is_admin**：アナリティクスダッシュボード等、通常の管理者画面へのアクセス権
- **is_super_admin**：上記に加え、10-3「高度な設定」へのアクセス権を持つ上位権限
- 判定は `sporive.profiles` の両フラグをリクエストごとに読んで行う（当初設計のカスタムアクセストークンフックによるJWTクレームは現行では使わない。[Requirements Auth](Requirements-Auth.md) §4-1）

## 10-3. 高度な設定

`is_super_admin`を持つ管理者のみメニュー表示・アクセス可能な設定画面。

**データ管理タブ（現行の実装）**：利用者単位または全利用者一括で、トレーニング計画・実績（`training_plans`/`plan_items`/`workout_logs`）、負債データ（`debts`）、AI提案ログ（`ai_proposal_logs`）、通知履歴（`notification_logs`）を完全削除できる破壊的な管理機能（`src/app/admin/settings/page.tsx`・`DataManagementPanel.tsx`・`actions.ts`）。`is_super_admin`であることをサーバー側でも二重チェックし、確認ダイアログを経由するが、削除は取り消し不可。詳細は[API](API.md)「管理者向け」節を参照。

以下の「機能タブ」「お知らせタブ」は要件定義当初の設計であり、**現在はadacの管理画面へ移行済み**（Sporive自身の管理画面からは削除済み）。過去の設計判断の記録として残す。

**機能タブ（旧・adacへ移行済み）**：サイト機能の一括ON/OFFトグル

| フラグ | 内容 |
|---|---|
| AI機能（マスタースイッチ） | 週間AI提案・AI改善提案・リカバリー提案・目標の自由記述要約を一括制御。各機能も個別にON/OFF可能 |
| 運動強度チェック | ルールベース判定（[Requirements AI Proposal](Requirements-AI-Proposal.md) §5-1）のためAI機能とは独立 |
| 新規ユーザー登録 | Sporiveの初回プロフィール登録（`/onboarding/profile`）の受付停止。ログイン・サインアップ画面はauthにあり、このフラグでは止まらない |
| 通知機能全体 | プッシュ通知の送信を一括停止 |
| 緊急メンテナンスモード | super-adminが任意のタイミングで即座にサイト全体をメンテナンス状態にできる手動スイッチ（[Requirements Notifications](Requirements-Notifications.md) §8-3参照） |
| 負債管理機能 | 負債の記録・リマインダー・補填提案を一時停止 |

**お知らせタブ（旧・adacへ移行済み）**：サイト全体向けのお知らせバー・お知らせ履歴（[Requirements Notifications](Requirements-Notifications.md) §8-4）を作成・管理する機能

- 入力項目：タイトル・本文・レベル
- **レベル**（3段階、専用CSSで色分け表示）

  | レベル | 用途 | 表示色 |
  |---|---|---|
  | お知らせ | 新機能案内・定期メンテナンス予告など通常の告知 | ネイビー（基調色） |
  | 注意 | 一部機能に影響する軽微な不具合・一時的な制限など | ティール（`accent-teal`） |
  | 警告 | 障害・緊急メンテナンス・重要な対応依頼など | コーラル（`accent-coral`） |

- **お知らせ・注意レベル**：影響範囲ページを選択可能（選択したページ名がお知らせ本文の下部に表示される。情報提供のみで機能制限はしない）
- **警告レベル**：開けなくするページを選択可能（選択したページは警告が有効な間、実際にアクセス不可になる）
- 定期メンテナンス予告（[Requirements Notifications](Requirements-Notifications.md) §8-3、1:00〜2:30のバー）は、この仕組みの中でシステムが自動投入する定期お知らせとして扱う
- ページの選択肢：ホーム・スケジュール・進捗・負債管理・お知らせ・アカウント設定・すべて

> **運用上の補足**：お知らせ・機能フラグの実体は現在 `saka2931-infra`（adac/statusと共有）の `service_announcements`・`feature_flags` テーブルに統合されており、作成・編集はadacの管理画面から行う。Sporive自身の管理画面からは削除済み。詳細は [Architecture](ARCHITECTURE.md) を参照。
