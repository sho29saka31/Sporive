# 要件定義書の更新

要件定義書（`docs/Requirements.md` と章ごとの `docs/Requirements-*.md`）に更新事項を反映するスキル。

## 手順

1. `docs/Requirements.md`（目次）から該当する章のページ（`Requirements-Auth.md` 等）を特定して読む
2. 該当章の記述を更新する
   - 既存のフォーマット（表・見出し・箇条書きのスタイル）を維持する
   - 複数の章・ページに影響する場合はすべての該当箇所を漏れなく更新し、記述間の矛盾を残さない
3. **必ず `docs/CHANGELOG.md` に変更記録を追記する**（このスキルが使われたら省略不可）
   - 形式: 先頭付近に `## YYYY-MM-DD（変更の見出し）` の節を追加し、箇条書きで「何をどう変えたか」と「理由」を書く（同じ日付の節があればそこへ追記）
   - 日付は今日の日付。理由が提示されていない場合はユーザーに確認する
4. 更新内容が `docs/Development-Plan*.md`・`docs/ARCHITECTURE.md`・`docs/ADR.md`・`CLAUDE.md` の記述と矛盾しないか確認し、影響がある場合はユーザーに報告する（勝手に書き換えず、更新するかを確認する）。設計判断を伴う変更は `docs/ADR.md` への追記を提案する
5. 変更をコミットする（コミットメッセージに更新概要を含める）

## 注意事項

- 既存の決定事項（`docs/CHANGELOG.md` の履歴で確定した内容）と矛盾する変更依頼の場合は、上書きしてよいかユーザーに確認する
- 今後の検討事項（`docs/Requirements-Future-Work.md`）が今回の更新で確定した場合は、そこから該当項目を「解決済み」へ移し、本文の該当章に反映する
- ログイン・アカウント関連の仕様は `auth.saka2931.jp`（authリポジトリ）が正。Sporive側の要件書は転送の挙動のみを記述する
